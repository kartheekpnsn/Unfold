# Lesson builder

You turn `T/_unfold/PRD.md` + `research.md` + `sources.json` into a working lesson page, where **T** is the topic folder (e.g. `topics/ML/DL`). It should look and feel like the reference lessons: `topics/Stacks/` (isometric SVG with sequencing and draw-on), `topics/LLM/` (a sequenced pipeline plus a three.js scene) and `topics/How-Do-Planes-Fly/` (three.js). Open their `_unfold/lesson.json` and `_unfold/scenes.js` before you start: they are the quality bar.

**You write data, not an app.** The player (`assets/player/`) is shared, hand-built code: tabs, stepper, narration pane, quiz, theme, keyboard, the three.js stage. You never edit it. You write two files and the build script does the rest:

```
T/_unfold/lesson.json   ← all text: tabs, steps, narration, quiz, sources
T/_unfold/scenes.js     ← animations: one object per scene id
T/index.html            ← generated by scripts/build-page.mjs (player + lesson + scenes + navigation, all inlined)
```

## Steps

1. **Read** `PRD.md`, `research.md`, `sources.json`, then these references:
   - `references/tabs.md`: the tab set per duration, each tab's job and budget, and the full `lesson.json` contract
   - `references/motion-and-visual-principles.md`: the seven motion rules every scene follows, and what render-check reports
   - `references/scene-cookbook.md`: the scene kit API, motion props, templates, styles, worked patterns, when and how to use three.js
   - `references/styles/<style>.md`: the spec for the PRD's style (and any alternates)
   - `references/writing-style.md`: voice per tab, narration rules, quiz rules
   - `references/design-tokens.md`: colours and their fixed meanings
2. **Write `scenes.js` first.** One scene per PRD scene id. Scenes are **state-based**: `render(state, prev, kit)` draws the whole picture for one step and the kit tweens from the previous picture. Keep keys stable for things that persist between steps (that's what makes them glide instead of blink). Plan each step as *before → after → what moved*: if only words change, it's a slide, so show the change (move, grow, draw on, count, sequence with `kit.seq`). Start from a template (`kit.pipeline`, `kit.timeline`, `kit.compare`, `kit.array`, `kit.stack`, `kit.graphWalk`, `kit.chartStory`) when one fits.
3. **Write `lesson.json`.** Set `style`, `altStyles` and any `tab.style` from the PRD. Copy sources from `sources.json` (id, title, url, publisher, trust note). Every narration that states a fact cites `[S#]`; every Technical step must cite. Respect the step budgets and the 60-word narration limit.
4. **Build:**
   ```
   node .agents/skills/lesson-builder/scripts/build-page.mjs T
   ```
   It validates first and writes `T/index.html` only if there are no errors. Validation covers the schema, tab set and order, step budgets, narration length, citations, and quiz rules. It also **dry-runs every scene for every step** (and the playground at each slider's min and max) against a mock kit, so a scene that throws or calls a kit function that doesn't exist is caught here. Fix every ERROR; fix warnings unless you have a reason (say it in the build log).
5. **Render-check (mandatory):**
   ```
   node .agents/skills/lesson-builder/scripts/render-check.mjs T
   ```
   It opens the built page in headless Chrome (Chrome, Chromium or Edge; set `CHROME_PATH` if it isn't found) and renders **every step of every tab** at 1280 px and 390 px, every playground control at its min and max, every 3D step with WebGL off, and every alternate style. It fails on clipped or overlapping labels, shapes outside the stage and runtime errors. It warns on sparse stages, text-only steps, jumps, re-keyed shapes and too many changes at once (see `motion-and-visual-principles.md` for what each means and how to fix it). It writes `T/_unfold/qa/contact.png` (one tile per step; red = errors, amber = warnings), `contact-390.png`, `contact-<style>.png` and `report.json`, and appends a "Render check" section to `build-log.md`. **Look at the contact sheets** and fix what you see, not just what the script reports.
6. **Loop** steps 4-5 until both pass, at most **3 loops**. Log each loop in `T/_unfold/build-log.md`: what failed, what you changed. Fix warnings unless you have a reason (say it in the build log). If no browser is available, say so in the report; never skip this step silently.
7. **Report**: build and render-check pass/fail, loops used, steps per tab, page size, styles, remaining warnings and why, and any PRD item you couldn't honour (and why).

## Non-negotiables

- `scenes.js` is a plain ES module with **no imports** and **no DOM access at module top level**. Everything arrives as `kit` (SVG) or `k3` (three.js).
- `export default { "<scene-id>": { mode, label, view?, mount?, render, fallback?, metrics?, note? } }`.
- Every three.js scene names an SVG `fallback` scene for devices without WebGL (the dry run exercises the fallback).
- Colours carry meaning: green = added/correct, red = removed/wrong, yellow = being looked at, blue = normal. Don't use red for decoration.
- No images, logos, film stills, photos of people, or lyrics. Diagrams, text and icons only.
- Never hand-edit `index.html` and never edit the player. If the kit lacks a primitive, compose it from `path`, `rect`, `text` and `raw()`, and mention the gap in your report.
- Use the PRD's style and its 3D choices: a `mode: 'three'` scene (with an SVG fallback) where the subject is spatial, layered or about scale, and the `3d` style for layered or structural scenes built from boxes. Page size is not a reason to avoid 3D.
- People appear only as generic figures (`kit.person`), never as likenesses of real people.

## Scripts

- `scripts/build-page.mjs <topic-folder>`: validate, then bundle into `index.html`. `--all --root topics` rebuilds every page; `--force` builds despite errors (don't).
- `scripts/validate-lesson.mjs <topic-folder>`: validation only (`--json` for machine-readable output).
- `scripts/render-check.mjs <topic-folder>`: render every step in headless Chrome and check layout and motion (`--all`, `--widths 1280,390`, `--frames` for mid-transition screenshots, `--no-log`, `--json`).
- `scripts/build-library.mjs [--root topics]`: rewrite `topics/index.html`, the library graph. `build-page.mjs` already does this after every build; `related.prereqs`/`next` ids and titles are what link lessons in it, so name them as a learner would search for them.
