# Lesson builder

You turn `T/_unfold/PRD.md` + `research.md` + `sources.json` into a working lesson page, where **T** is the topic folder (e.g. `topics/ML/DL`). It should look and feel like the two reference lessons, `topics/Stacks/` (isometric SVG) and `topics/How-Do-Planes-Fly/` (three.js). Open their `_unfold/lesson.json` and `_unfold/scenes.js` before you start: they are the quality bar.

**You write data, not an app.** The player (`assets/player/`) is shared, hand-built code: tabs, stepper, narration pane, quiz, theme, keyboard, the three.js stage. You never edit it. You write two files and the build script does the rest:

```
T/_unfold/lesson.json   ← all text: tabs, steps, narration, quiz, sources
T/_unfold/scenes.js     ← animations: one object per scene id
T/index.html            ← generated by scripts/build-page.mjs (player + lesson + scenes + navigation, all inlined)
```

## Steps

1. **Read** `PRD.md`, `research.md`, `sources.json`, then these references:
   - `references/tabs.md`: the tab set per duration, each tab's job and budget, and the full `lesson.json` contract
   - `references/scene-cookbook.md`: the scene kit API, worked patterns, when and how to use three.js
   - `references/writing-style.md`: voice per tab, narration rules, quiz rules
   - `references/design-tokens.md`: colours and their fixed meanings
2. **Write `scenes.js` first.** One scene per PRD scene id. Scenes are **state-based**: `render(state, prev, kit)` draws the whole picture for one step and the kit tweens from the previous picture. Keep keys stable for things that persist between steps (that's what makes them glide instead of blink).
3. **Write `lesson.json`.** Copy sources from `sources.json` (id, title, url, publisher, trust note). Every narration that states a fact cites `[S#]`; every Technical step must cite. Respect the step budgets and the 60-word narration limit.
4. **Build:**
   ```
   node .agents/skills/lesson-builder/scripts/build-page.mjs T
   ```
   It validates first and writes `T/index.html` only if there are no errors. Validation covers the schema, tab set and order, step budgets, narration length, citations, and quiz rules. It also **dry-runs every scene for every step** (and the playground at each slider's min and max) against a mock kit, so a scene that throws or calls a kit function that doesn't exist is caught here. Fix every ERROR; fix warnings unless you have a reason (say it in the build log).
5. **Loop** step 4 until it prints ✓, at most **3 loops**. Log each loop in `T/_unfold/build-log.md`: what failed, what you changed.
6. If your tool can open a browser or view screenshots, open `T/index.html` and look at ELI5 step 1, two Core steps and one Technical step. Fix overlapping or clipped labels and off-centre or empty-looking stages. The main object should fill roughly the middle 60% of the stage. If you can't, rely on the patterns in the cookbook and the reference scenes.
7. **Report**: build pass/fail, loops used, steps per tab, page size, and any PRD item you couldn't honour (and why).

## Non-negotiables

- `scenes.js` is a plain ES module with **no imports** and **no DOM access at module top level**. Everything arrives as `kit` (SVG) or `k3` (three.js).
- `export default { "<scene-id>": { mode, label, view?, mount?, render, fallback?, metrics?, note? } }`.
- Every three.js scene names an SVG `fallback` scene for devices without WebGL (the dry run exercises the fallback).
- Colours carry meaning: green = added/correct, red = removed/wrong, yellow = being looked at, blue = normal. Don't use red for decoration.
- No images, logos, film stills, photos of people, or lyrics. Diagrams, text and icons only.
- Never hand-edit `index.html` and never edit the player. If the kit lacks a primitive, compose it from `path`, `rect`, `text` and `raw()`, and mention the gap in your report.
- Use 3D only where the PRD says `three` (it adds ~1 MB of three.js to the page).

## Scripts

- `scripts/build-page.mjs <topic-folder>`: validate, then bundle into `index.html`. `--all --root topics` rebuilds every page; `--force` builds despite errors (don't).
- `scripts/validate-lesson.mjs <topic-folder>`: validation only (`--json` for machine-readable output).
- `scripts/build-library.mjs [--root topics]`: rewrite `topics/index.html`, the library graph. `build-page.mjs` already does this after every build; `related.prereqs`/`next` ids and titles are what link lessons in it, so name them as a learner would search for them.
